# 卸载残留与长期未更新的功能目录

当扫描涉及 App Support、Containers/Group Containers、更新缓存或隐藏工具目录时读取。首次报告需主动给“疑似卸载残留与长期闲置功能”短清单，不能等用户逐路径问软件名字。此文是证据判断流程，不是卸载器或固定删除白名单。

## 候选发现和归属

macOS 可从本次扫描批量筛选 ≥100 MiB 的应用/隐藏用户目录（默认最多30个；遗漏列表必须披露）：

```bash
python3 scripts/app_evidence_macos.py --scan-json /tmp/storage_scan.json > /tmp/storage_app_evidence.json
# 用户指定目录不限大小；需要核对占用时添加 --check-open-files
python3 scripts/app_evidence_macos.py /absolute/data/path --check-open-files > /tmp/storage_app_detail.json
```

脚本读取 /Applications、~/Applications、/System/Applications 及一层子目录的 App 元信息，查候选里的嵌套 `.app`、容器标识、内置HTML标题、manifest供应商域名，并列输入法/音频插件元信息及匹配的启动项。默认每候选20秒/3万文件，不跟符号链接，跳过node_modules/.git；不执行目标程序、不输出模型配置/密钥/聊天内容。它不证明卸载、不验证全部共享依赖；根目录之外的插件使用者、其他安装位置、系统扩展和嵌套标题缺失时仍需针对性核对。Windows 用原生安装应用/包元信息、AppData与服务核验，不套用macOS脚本，不宣称实测。

归属证据按强弱区分：
1. Bundle ID和应用元信息、容器MCM标识及可复核映射，可以确认对应产品/组件；精确名称匹配仍只是候选。
2. 内置网页入口的明确产品标题、资源清单，可辅助确认。例如 TDAppDesktop 内 docs.qq.com/desktop/index.html 标题“腾讯文档”，比目录名有力。
3. 供应商下载域名只能说明来源。例如 `.real` 的 manifest 含钉钉资源URL，不能直接把未证实的产品名“悟空”写成事实。
4. 只有路径名、系统未搜索到App、旧时间，均不足以确认归属或可删。

必须分开记录：主App是否在已检查位置、数据目录内是否还有手动版本App副本、是否有启动项/服务、是否有输入法/音频驱动等系统组件，以及实际进程/文件占用。未查到的状态叫“在已查范围未发现”，不叫“已完全卸载”。用户明确说已卸载默认采信；发现另一份副本应解释位置，不反过来否认用户。

## mtime是重要建议因素，但不是删除许可

`deep_scan.py` 输出 `activity`：根目录mtime、内部文件最新/最旧mtime、按月分布、最新10个文件；按 `--stale-days`（默认180天，可按场景调整）统计旧文件数量和分配体量，每个直接子项也有旧文件体量与最新mtime。

- 报告主动指出“特定功能目录占X，其内部文件最新变化为Y，约Z个月未更新”；这是筛选大而闲置功能的高价值信号。给出具体建议：保留运行功能、只清旧资源/历史版本，或作为已停用应用残留候选。
- 用内部文件和关键数据文件时间，不只看文件夹mtime。脚本另给排除`.DS_Store`、`desktop.ini`等文件管理器元数据后的内容最新变化，避免“今天打开访达”被误报为“功能今天仍有更新”；原始mtime仍保留，不能隐瞒。根目录日期新可能只是元数据变化；反之，文件夹日期旧不说明内部内容未更新。
- 看子功能、版本目录分别的日期和体量，避免一条新日志掩盖几GiB旧资源。安装副本常保留构建时间，不等于这天最后运行；复制/解压也会影响时间。
- **有当前进程、系统加载组件、CurrentProfile/当前路径配置、用户明确在用/保留时，旧mtime不能覆盖这些证据。** 旧壁纸仍可能正在显示，旧运行时仍可能被当前工具调用。
- 不读/不用atime证明最后使用，扫描自身可能影响访问时间。缺权限/限额时只说“已覆盖部分的最新变化”，不推断整目录长期未用。未来时间或时钟矛盾要说明，不能算成闲置。

例如旧企微Profile全部文件停在4月且CurrentProfile不指向它、lsof无占用，可建议先清约150MiB功能资源，保留聊天与配置；不能将Profile哈希、数字VID和企业名称直接等同。腾讯文档内部文件长期停在2025年2月是停用线索；用户确认不用且本地资料不要后，才可处理整个目录。

## 共用组件、账户、媒体库

- App卸载不代表组件无人用：Doubao 中藏旧App副本；音频插件可能由系统加载，而用户仍用豆包输入法。分别核验桌面App目录、DoubaoIme、HAL音频插件，不能凭品牌相同证明共用，也不能凭App不在证明无依赖。共享关系不明的核心组件保留，不提供删除路径。
- iwallpaper：精确Bundle ID命中，进程运行且Wallpaper打开其图片，这是在用证据。用户说保留后，本轮不再把它或其子目录反复列清理候选；可解释占用，但不能给删除按钮。
- 多账户：用CurrentProfile/当前账户配置+lsof匹配活跃目录；文件时间作佐证。旧Profile可只清资源、保留资料。无法解出企业名映射就保留“身份未映射”，不凭群名或文件夹猜公司。
- 图库：拆开 originals 原件、缩略/派生图、搜索索引、数据库。originals为空不表示整个图库无用或无云端关系；Wallpaper/Spotlight/照片服务可能仍维护它。区分“删除照片内容”“移除本地图库包”“关闭本机同步”和“账户级删除云端”。同步状态只作为已观察证据，不在存储分析中擅自改设置。用户截图显示“同步此Mac”已关就承认满足，不反复要求找不存在的常驻“移除”按钮；仅在关闭时可能弹出。涉及后续图库清理前核对本机同步和占用，不建议账户级删除云端。

## 报告必须交付什么

在执行建议中先列高价值残留候选，再给所有目录明细；每项写：软件名/置信度与来源、安装/内嵌副本状态、运行/当前身份/共享依赖、内部最近变化、具体占用、建议粒度（保留/旧资源/整个残留需用户确认）、清理影响与恢复。未知产品不是终点：先尝试上面的本地元信息路线，仍无证据才标未知并保留。

`user_decision: "keep"` 表示本轮明确保留，`cleanup_blockers: ["共享依赖未核清"]` 表示这条精确路径存在阻断；生成器/服务会去掉它以及与它重叠的清理白名单和旧命令。这不是持久化偏好文件。当前在用的主程序/核心数据保留；已明确可再生的独立缓存可以写退出条件后另列，不将“App运行”一刀切成所有缓存永不能清。

用户明确授权删整个残留且本地资料不要时，直接按既定授权验证后移废纸篓，不再强行拆成资源/资料重复询问；若还存在未解决共享依赖，只暂停对应组件，继续独立可完成的已授权对象。不要扩大到同品牌输入法、驱动或其他目录。
